REST API

Everything in the platform is available through a versioned REST API at /api/v1. The Admin Studio uses the same API.

Interactive documentation

Every installation serves an OpenAPI 3.1 document at /api/v1/openapi.json and interactive docs at /api/v1/docs. /api/v1/openapi/tenant.json adds typed schemas and paths for your own entities.

Authentication

API keys (servers, apps, scripts)

Create a key under API keys in the Admin Studio and send it as a bearer token:

```bash curl -H "Authorization: Bearer bcms_1a2b3c4d_xxxxxxxxxxxxxxxxxxxx" \ https://cms.example.com/api/v1/entities/article/records ```

A key belongs to one workspace and is limited to its scopes. Keys cannot manage members or other keys.

Browser sessions

POST /api/v1/auth/login sets an httpOnly session cookie and returns the session, including a csrfToken. Every state-changing request made with the cookie (POST, PATCH, DELETE) must send the token in the x-csrf-token header. Bearer-token requests don't need it.

```bash curl -c cookies.txt -H "content-type: application/json" \ -d '{"email":"ada@acme.com","password":"…"}' \ https://cms.example.com/api/v1/auth/login ```

Conventions

  • Requests and responses are JSON. The request body limit is 1 MB by default.
  • Successful responses wrap their payload: { "data": … }, and lists add "meta".
  • IDs are UUIDs. Timestamps are ISO 8601 in UTC.
  • Every response has an x-request-id header. You may send your own.
  • Resources of other workspaces always return 404.

Create

```bash curl -X POST https://cms.example.com/api/v1/entities/product/records \ -H "Authorization: Bearer $API_KEY" -H "content-type: application/json" \ -d '{"data": {"name": "Desk lamp", "price": 19.9}}' ```

Missing fields get their default values. Unknown fields, invalid values and missing required fields return 422 with details per field.

Update with concurrency control

Send only the fields to change. Include the version you last read to avoid overwriting someone else's change:

```bash curl -X PATCH https://cms.example.com/api/v1/entities/product/records/$ID \ -H "Authorization: Bearer $API_KEY" -H "content-type: application/json" \ -d '{"data": {"price": "24.50", "stock": null}, "version": 3}' ```

If the record changed meanwhile, the API answers 409 RECORD_VERSION_CONFLICT with details.currentVersion.

Filters

filter[field]=value means equals. filter[field][operator]=value uses an operator:

OperatorMeaningExample
eq, neEqual / not equalfilter[status][ne]=draft
gt, gte, lt, lteComparisons (numbers, dates)filter[price][lt]=100
inOne of a comma-separated list (up to 100)filter[status][in]=draft,review
containsText contains (case-insensitive), or a multi-value field contains a valuefilter[tags][contains]=sale
startsWithText starts withfilter[name][startsWith]=desk
isNullField is empty (true) or set (false)filter[stock][isNull]=true

System attributes work too: filter[id][in]=…, filter[createdAt][gte]=2026-01-01T00:00:00Z. Up to 20 conditions are combined with AND. Which operators work depends on the field type. Unknown fields or unsupported operators return 400 INVALID_FILTER. You can only filter, sort and select fields your role or key may read.

Rate limits

By default each client (API key or IP address) may make 600 requests per minute. Login and setup are limited to 10 attempts per minute per IP. Administrators can change both. See Configuration.
